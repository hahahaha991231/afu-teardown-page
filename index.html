五条核心结论

  • 定位上，阿福把「AI 健康朋友」落成三个入口 —— 阿福（即时提问、报告解读、AI 诊室、找医生）、健康（饮食活动与设备数据）、就医／我的（医疗服务、订单、家庭成员与健康档案），同时承接偶发需求与持续需求。
  • 结构上，产品是一个底座（蚂蚁医疗大模型）+ 三大模块（健康问答／健康陪伴／健康服务）+ 三层供给（AI 自服务 → 名医 AI 分身 → 真人医生）。
  • 效果上，用一个连续场景（看不懂体检报告 → 报告解读 → 多轮追问 → 就医服务 → 健康档案）测试，能力维度评测表合计 81/100，落于「主流程可用，个别解释或跳转需要用户补充、核对」一档。
  • 技术上，表层是一句健康疑问，底层是模拟医疗团队分工的多智能体系统：1 个主控 Agent 负责识别、拆解、编排、汇总，多个专科／角色子 Agent 并行承接，全部共享一份病例级 case_context。
  • 商业上，C 端咨询与报告解读免费，用免费换入口，再把确有需要的用户导向挂号、问诊、购药、支付等服务；但阿福具体从哪些服务收费、如何分成、AI 业务何时盈利，公开资料不足以确认。

二

产品介绍：一个底座 + 三大模块 + 三层供给

按三入口（阿福 / 健康 / 就医·我的）整理功能表，并区分偶发需求与持续需求
定位一句话：蚂蚁阿福是蚂蚁集团旗下把 AI 做成「健康朋友」的应用。

1.1 一个底座：蚂蚁医疗大模型

  • 由蚂蚁集团自研，学习海量专业医疗文本语料，具备医学推理能力，可完成图文、语音、视频等多模态交互，在 HealthBench、MedBench 等评测中处于行业前列。
  • 训练阶段联合全国 200 余家三甲医院、1000 余位名医共同参与，其中包含 6 位院士；依托浙江国家医疗人工智能基地的技术与资源支持；据公开报道，团队成员中约六成具备医学背景。
  • 回答的逻辑是模拟真实医生的问诊流程，而不是搜索引擎式的信息拼凑；用户反馈中出现频率很高的一句话是「它说的和医生说的差不多」。

1.3 三层供给：从 AI 自服务到真人医生

第一层 · AI 自服务
日常头痛脑热、报告解读、用药疑问，阿福直接回答，7×24 小时在线
第二层 · 名医 AI 分身
由院士、学科带头人等名医的数字分身承接专业咨询，把院士与名医的经验复制给更多人
第三层 · 真人医生
接入 30 万名真人医生在线问诊，并可继续完成挂号、就诊与支付

产品还上线了「医生把关」功能，在行业内较早落地「AI 问答 + 医生复核」的协作模式，让 AI 的回答多一道人工防线。

三入口功能表（阿福 / 健康 / 就医·我的）

产品被拆成三个入口，这意味着它希望同时服务偶发需求与持续需求。

入口功能需求类型判断依据
阿福 即时提问、报告解读、AI 诊室、找医生 偶发 偶发需求指「突然看不懂一份报告」，对应即时提问与一次性解读
健康 饮食、活动、设备数据与日常记录 持续 持续需求指「长期管理本人及家人健康」，对应日常记录与设备同步
就医／我的 医疗服务、订单、家庭成员与健康档案 持续 + 偶发 健康档案与家庭成员是长期沉淀；订单与医疗服务多为一次性办事。未对这两项分别归类，此处为按上述定义的推断

更细的三分法：健康咨询（AI 诊室、报告解读、拍皮肤、打电话，侧重即时解答）、就医协助（就医服务、查医保，侧重实际办事）、持续健康管理（药管家、健康小目标，侧重持续执行）。

三

效果体验：用一个连续场景测试能力

测试场景：看不懂体检报告，接下来怎么办？任务链：报告解读 → 必要追问 → 就医服务 → 健康档案

测试场景与任务链

本次选择「报告解读 ＋ 多轮咨询 ＋ 就医服务」作为贯穿场景，理由是它能同时覆盖「报告解读」「AI 诊室」「健康档案」「科室推荐」「找医生」等入口，适合观察阿福能否把一次提问推进为完整任务。

报告解读
上传模拟 PDF，先看报告原文写了什么
必要追问
不退出对话继续提问，核对风险与信息缺口
就医服务
科室推荐 / 找医生，从解释走向行动
健康档案
选择就诊人、保存并回看材料
起点：报告写有「肺结节」，用户看不懂影像描述，也不知道应不应该复查、去哪个科室。
目标：看懂报告原文，明确还缺少哪些判断信息，找到合理的下一步服务。

五个连续场景

场景动作与对话测试点
场景一
疑问 · 报告刚到手
晚上，用户在家收到母亲发来的体检报告，看到「右肺上叶小结节」几个字，放大图片反复看，却不知道「5 mm」意味着什么。		 动作：打开阿福 App，从首页点击「报告解读」，上传准备好的模拟 PDF。
对话：「我看不懂这份报告。先告诉我报告具体写了什么，哪些是需要关注的信息。请不要补充报告里没有的内容。」		 它能否读准部位、项目、大小和报告结论？是否把原文和自己的解释区分开？
场景二
焦虑 · 追问风险
读完解释，用户仍然停留在「结节」两个字上，想知道是不是应该立刻带母亲去医院。		 动作：不退出当前对话，直接继续提问。
对话：「看到'结节'我有点害怕。仅凭这份报告，你能确定什么？还有哪些信息不足，不能直接下结论？」		 它会不会把报告解读说成确定诊断？是否能清楚告诉用户下一步需要核对哪些信息？
场景三
转折 · 这不是我的报告
用户发现自己从头到尾都说「我」，但这份报告其实属于母亲。若系统把信息记到本人名下，后续建议就可能混乱。		 动作：主动纠正报告归属。
对话：「我刚才漏说了，这是我 62 岁妈妈的报告，不是我的。请按她的情况重新整理刚才的结论，并告诉我你还缺少什么信息。」		 阿福能否及时纠正上下文？后续会不会继续把母亲的报告说成本人的报告？
场景四
行动 · 从解释走向就医
用户不再只想知道术语含义，而是想帮母亲找一位合适的医生。		 动作：在当前对话提问，然后尝试进入「科室推荐」或「找医生」。
对话：「我想带妈妈找医生进一步咨询。从哪个科室入口开始比较合适？阿福里能帮我完成哪些步骤？」		 健康咨询与就医服务之间有没有断点？阿福是否解释推荐理由，并让用户自己确认选择？
场景五
收尾 · 保存后再反问
希望下次陪母亲就医时还能找到原报告和这次咨询记录。		 动作：打开「健康」或「我的」中的「健康档案」，查看能否选择母亲作为就诊人并保存、回看材料，随后返回阿福对话。
对话：故意问：「请总结一下我本人这次胸部 CT 的结果。」		 它能否指出「刚才上传的是你母亲的报告」？是否避免将母亲的健康信息写进本人档案？

5、分数评级与四维对照

分数评级

  • 90–100 分：报告读取准确，追问有效，跨功能信息一致，用户能清楚完成下一步。
  • 70–89 分：主流程可用，个别解释或跳转需要用户补充、核对。
  • 60–69 分：部分功能有价值，但报告信息、上下文或功能衔接存在明显断点。
  • 60 分以下：关键内容频繁出错，难以可靠完成这项任务。
本次合计 81 分，落在 70–89 档，即「主流程可用，个别解释或跳转需要用户补充、核对」。

与同类产品的差异点：公开方向对比

它的差异需要从用户使用场景和服务组织方式来理解。

产品公开介绍强调的方向对阿福分析的启示
蚂蚁阿福 AI 健康朋友；健康咨询、个人及家庭档案、医疗服务连接。 可以围绕日常陪伴和家庭健康需求分析
讯飞晓医 医疗专业能力、个人数字健康空间，以及症状、用药、报告和慢病管理。 是最直接的竞品；档案、报告解读、健康管理都不能算阿福独有

它们的功能重叠很多。现在更有依据的是分析定位与体验侧重，效果上的优势还需要同场景对照。

三条差异点

1. 将使用场景延伸到日常健康陪伴
通过健康小日记、小目标、小提醒等功能，把场景延伸到日常记录和习惯养成，同时支持管理自己及家人的健康信息。体现它希望建立持续使用关系。

讯飞晓医同样提供健康档案和健康管理，因此这里的差异应表述为阿福对「健康朋友」和日常陪伴的强调，不能认定为独有功能。
2. 用对话帮助用户整理尚未表达清楚的问题
面对「我很难受」这样模糊的描述，阿福先提示安全事项，再列出需要补充的关键信息、需要警惕的信号和后续可继续讨论的方向，整个过程在聊天页面内完成。在明确要求一次只问一个问题后，它能够调整追问节奏。

由于尚未与竞品进行同场景比较，不能据此认定其追问能力更强或医学判断更准确。
3. 将咨询、健康信息管理与医疗服务连接组合起来
应用说明列出了图片解读、个人及家庭健康档案管理，以及预约挂号、云陪诊等服务，尝试覆盖从理解健康问题、整理资料到寻找医疗服务的连续需求。

京东健康也提供 AI 咨询与真人问诊入口，因此值得比较的是服务如何衔接：是否需要重复描述问题、资料能否带入下一步、需要几次操作才能找到合适的服务。

用完整任务链检验竞争力

它的竞争力要通过一条完整任务链来检验 —— 报告解读 → 必要追问 → 就医服务 → 健康档案。

报告解读
能否读准原文并分离「原文」与「解读」
必要追问
追问是否必要且自然，能否接受纠正
就医服务
能否从解释无断点走向科室推荐与找医生
健康档案
能否区分本人与家人并正确落档
检验结论：本次网页体验确认了健康问答和医学资料检索能力，但没有完成指定医院官网挂号入口的查找。因此，目前可以写『产品提供医疗服务连接』，尚不能写『已验证完整就医闭环』。

定位小结

阿福的差异不在单一功能，而在把三类能力组织成一条用户路径：即时问答解决「这一刻看不懂」，日常陪伴与档案解决「长期记不住」，医疗服务连接解决「知道了下一步去哪儿」。功能与竞品高度重叠，差异目前只能落在定位与体验侧重，效果优势仍需同场景对照。

感知层由多模态解读 Agent 与一组输入工具共同承担：拍皮肤（识别常见皮肤问题）、读检验报告（覆盖 99% 常见报告）、识别药盒并解读用药信息、拍饮食估算热量与营养结构；同时支持语音、文字、图片、PDF 与设备数据。报告解读 Agent 的输入契约要求每次激活先核对材料是否清晰可读（quality_score ≥ 60）、报告所属人是否已确认、用户是否要求多报告对比。

记忆层是一份病例级任务上下文 case_context，「像本次咨询的共同工作单，让不同 Agent 使用同一组事实和引用」。字段含 case_id、version、status、user_goal、subject_id、subject_confirmed、consent_scope、input_artifacts[]、extracted_facts[]、user_provided_facts[]、open_questions[]、task_plan[]、evidence_refs[]、risk_flags[]、outputs[]、decision_log[]。关键机制是强引用关系与遗忘：若 subject_id 改变，依赖旧对象生成的解释、推荐和保存请求要被标记为待重新核对；过期信息遗忘，冲突信息 100% 确认才用。
规划任务拆解与编排（主控 Agent · 构成推导）
规划由主控 Agent 承担，它「更适合采用有状态的规划与执行方式，而不是一直依靠一段越来越长的自由对话来记事」，四件事：规划（识别目标、列出子任务和先后依赖，例如先读报告再围绕读到的内容追问）、执行（调用对应 Agent 或工具，记录每一步输入输出与状态）、检查（在报告归属、事实提取、风险提示、档案写入等节点设置校验）、回退（用户纠正上游事实时，从受影响的节点重新推进，而不是只改最后一段话）。
工具工具与接口（4.3 Tool）
每个 Agent 都有各自的工具推导表，另设 4.3 Tool 一节做全局归纳，按类别给出建议名称与主要使用者：文件接收、图像/文档解析、图像质量检查、语音转写与播报、问诊表单、医学知识检索、药品说明书检索、就诊人及权限检查、健康档案读写、设备数据接入、医生/医院搜索。工具调用必须由主 Agent 明确提供并授权，工具失败要说明失败及影响，不把「未查到」视为「不存在」。
行动评估评估与门禁（评测表 · 越界评测）
行动评估有两条线。产品侧是效果评测：4 个能力层级、9 个评测维度、合计 100 分，本次合计 81 分。工程侧是越界行为评测：评测集内置对抗性用例（如冒充医生、越权承诺功能），以红线用例通过率作为上线门禁（release gate）。此外还有结果校验工具负责「检查主体一致性、事实引用、缺失信息和风险标记」。
安全护栏硬约束与旁路（安全体系）
安全体系遵循「生成能力与硬性约束相分离」的工程原则，四类机制构成纵深防御：其一，高危语义黑名单与触发式响应——胸痛、自杀意念等高危关键词确定性匹配，命中即旁路（bypass）生成模型，强制输出预设就医干预话术；其二，强制引用协议——回答必须携带可溯源证据链，检索未命中触发拒答；其三，数据最小化与用户控制权——仅采集必需字段，支持导出与删除；其四，越界行为评测作为上线门禁。另有专门的心理危险干预 Agent，原则是「生命优先于对话，高危时 AI 停止自由发挥，转入确定性干预流程」。

5.2 逻辑

  • 构成：模型层不是一个模型，是一个池子加一层路由。池子是三类模型加一道护栏。百灵管语言、推理和调工具，安诊儿管医学知识和循证口径，Ling-3.0-flash-VL 管看图读报告，SingProbe 挂在生成过程里打风险分，额外开销低于 0.5%。
  • 路由怎么分：按四件事判断 —— 问题简单给小模型，复杂推理给万亿思考模型，带图给多模态，碰到用药、孕产、心理这类高敏话题走带溯源和医生把关的那条路。
  • 为什么这么分：小激活模型省钱省时间，日咨询两千万次的量级下这是硬约束；医学知识更新快，用专用模型装比让通用模型去背指南靠谱；安全和生成拆开，换模型时安全水位不会跟着抖。
  • 可替换与未公开：模型本身是可替换件，接口、数据、评测都统一，所以阿福的功夫主要花在应用层。线上具体跑哪个版本、怎么配比，没有公开。

6、基础层：数据 + 知识 + 检索 + 评测底座

定义：支撑上层 AI 能力（问答、报告解读、导诊、陪伴）的数据 + 知识 + 检索 + 评测底座。用户看不到它，但它直接决定答案准不准、引用可不可信、产品敢不敢上线。

为什么重要：大模型 API 时代，各家的「对话能力」趋同；真正拉开差距的是你喂给模型什么数据、用什么知识库、怎么保证不胡说。基础层 = 产品差异化所在。

机制内容
